4 量化项目管理

约 5516 字大约 18 分钟

2026-11-24

4.1 量化管理的含义

量化管理是指以数据为基础，用统计或其他量化的方法来分析和研究事物的运行状态和性能，对关键的决策点及操作流程进行管理监控，以求对事物存在和发展的规模、程度等做出精确的数字描述和科学控制，实施标准化操作的管理模式。

量化管理理论是一种从目标出发，使用科学、量化的手段进行组织管理体系的设计并为具体工作建立工作标准的理论，它涵盖了组织战略制定、组织管理体系建设、对具体工作进行量化管理等各个领域。

4.2 量化管理理论

4.2.1 科学管理理论

量化管理的基础之一是科学管理理论，诞生于 19 世纪末，由美国工程师和管理学家弗雷德里克·泰勒（F. Taylor，1856—1915）创建。泰勒通过大量实验研究，总结出科学管理的五大原则：

原则内容
工时定额化研究工人工作时动作的合理性，去掉多余动作、改善必要动作；规定完成每一个工作单位操作的时间，制定合理的劳动时间定额
分工合理化对工人进行科学的选择、培训和晋升，选择合适的工人安排在合适的岗位；培训工人使用标准操作方法
程序标准化制定科学的工艺规程，使工具、机器、材料标准化，作业环境标准化并用文件固定下来
薪酬差额化把工作任务完成情况与工资收入关联，实行具有激励性的计件工资制度
管理职能化管理和劳动工作分离，管理者和劳动者密切合作但职责不同，保证工作按标准的设计程序进行

量化管理理论吸收了科学管理的理念：①任务定额化——确定标准任务或可量化目标并逐步细化分解；②程序标准化——为每个管理对象和工作环节制定标准流程，降低流程变异性，为数据分析奠定基础；③薪酬差额化——按劳取酬，把完成工作的质和量与报酬紧密联系。

彼得·德鲁克曾说过：没有度量，就没有管理。量化管理当前已被各行业广泛采用，旨在提升管理的精细化程度和管理效率。

4.2.2 统计过程控制（SPC）

统计过程控制是指应用统计技术对工作过程中的各个阶段进行分析、监控和评估，建立并保持工作过程处于可接受的并且稳定的水平，从而确保产品与服务符合规格要求的一种管理技术。

1924 年，休哈特将数理统计用于制造过程的质量控制，创立了以控制图为核心的 SPC 理论，目的在于预防或减少生产过程中出现不合格品的概率，实现质量管理从事后把关向事前预防的转变。

统计过程控制是一种预防性方法，强调全员参与，强调整个过程。它重点解决组织的两个问题：一是工作过程运行的状态是否稳定（用控制图分析判断）；二是过程能力是否满足规格要求（用过程能力分析方法判定）。

SPC 认为过程的能力存在波动性：一种是正常波动（任何组织或个人执行过程都会有一定的波动性，这是正常的）；另一种是异常波动（有特殊成因造成，需要识别并管理）。

控制图基于正态分布原理：

区间落入概率
均值 ± 1σ约 69%
均值 ± 2σ约 95%
均值 ± 3σ约 99.73%

样本数据落在 ±3σ 之外的概率为 0.27%，根据统计学通用规则，一般小于 5% 的概率称为小概率事件；生产过程中一旦出现小概率事件，意味着过程出现了异常情况。通过正态分布原理，可以从控制图上分清波动是正常成因还是异常成因。

基于数据统计分析的量化管理行为可分为 3 个层面：①描述和分析组织或项目的特征（现状、结构、因素之间的关系）；②分析组织或项目的运行规律与发展趋势（动态数据）；③对组织或项目的未来状态进行预测（建立预测模型）。

4.2.3 量化管理应用：六西格玛与 CMMI

1. 六西格玛（Six Sigma，6σ）

六西格玛是一种改善组织质量流程管理的技术，强调“零缺陷”的预防控制和过程控制。其原理是，如果检测到项目中有多少缺陷，就可以找出如何系统地减少缺陷的方法。组织要达到六西格玛标准，按照正态分布特征，出错率不能超过 0.00034%。

六西格玛的业务流程改进遵循 5 步循环改进法，即 DMAIC：

步骤内容
定义（Define）识别需要改进的产品或过程，确定改进项目所需的资源
度量（Measure）定义缺陷，收集产品或过程的表现作为工作基准，建立改进目标
分析（Analyze）分析度量阶段收集的数据，确定一组按重要程度排列的影响过程和产品质量的变量
改进（Improve）优化业务流程，并确认方案能够满足或超过项目质量改进目标
控制（Control）建立有效的控制手段，确保过程改进完成后能够继续保持，不返回到改进前的状态

六西格玛是一种基于数据统计分析的管理方法，强调用数据客观体现管理流程的能力，其代表特征是管理流程、管理指标的量化。

2. CMMI

CMMI 将组织的管理成熟度划分为 5 个级别，成熟度级别越高，对量化管理的要求越高。当达到 4 级（量化管理级）和 5 级（优化级）时，要求组织针对过程的管理能够量化分析和量化预测。高成熟度组织的主要特征包括：

  1. 建立量化的目标管理机制：从战略规划到业务目标，再到质量与过程性能目标，都以量化形式表达和管理，并分解到各过程、子过程；
  2. 建立过程能力量化监控机制：对过程能力建立量化能力指标，识别能力稳定性，发现过程变异的特殊成因并及时修正；
  3. 建立目标的量化预测能力：对量化目标进行预测，对可达成情况进行量化分析，及时调整过程投入或方式；
  4. 建立基于量化的持续优化机制：预测变化对过程和投资回报的影响，量化评价过程改进对业务目标达成的支撑情况。

4.3 组织级量化管理

组织开展量化管理工作的前提在于该组织已经定义了产品或项目管理的组织级标准过程，各产品或项目团队能够遵循组织统一的管理流程、规程和产出要求开展工作，组织收集的度量数据才具备统计意义。

建立组织级量化管理体系的内容主要包括：定义组织量化过程性能目标、识别关键过程、建立度量体系及数据收集、建立过程性能基线和建立过程性能模型。

4.3.1 定义组织量化过程性能目标

组织项目管理方面量化性能目标在 CMMI 模型中称为质量与过程性能目标（QPPO），通常包括质量方面和过程性能方面。根据行业基准数据统计，组织重点关注的项目管理能力量化目标通常包括生产率、交付缺陷、交付工期偏差、客户满意度等。目标设定必须支持组织战略规划和业务目标，并确保可量化、可验证，可用 SMART 原则检验。

组织在定义目标时，还应依据目标对战略规划及业务目标的影响程度排定优先级。当存在多个目标且达成条件互相制约时，可使用优化组合方法遍历不同过程方案，选择最能达成目标的最优过程组合。

需要检查目标与实际偏差并修订目标的情况包括：①业务目标发生变化时；②组织的标准过程体系结构及过程发生变化时；③实际的质量与过程性能同制定的目标严重偏离时；④组织架构进行重大调整时。

判定目标可达成性可参考过程能力指数（CPK）：

CPK 取值判断
≥ 1.33过程能力良好，状态稳定，可满足目标要求
1.00 ～ 1.33可满足目标要求，但过程能力状态一般，稍有变异即可能导致目标无法达成
0.67 ～ 1.00存在不稳定性，达成目标有一定风险，需改进提升能力
< 0.67不能满足目标要求且风险较大，必须重新定义流程或大幅调整资源投入，或重新制定目标

目标分解方式与管理模式相关：强矩阵型管理模式下，组织级目标应根据业务条线和项目集特征分解至各个项目；职能型管理模式下，可依据职能划分，将目标分解至负责需求、设计、开发、测试、集成和运维等职能部门。

4.3.2 识别关键过程

组织资源有限，需要根据已定义的质量和过程性能目标选择出对目标达成关键的过程或因素，定义其度量属性并开展量化管理。关键过程选择准则包括：

  1. 过程或子过程是质量与过程性能目标的主要贡献者；
  2. 过程或子过程是目标的重要预测器；
  3. 过程或子过程对了解达成目标的关联风险是重要因素；
  4. 过程和子过程与关键业务目标强相关；
  5. 过程或子过程在过去已证明是稳定的；
  6. 过程或子过程相关的有效历史数据当前可使用；
  7. 过程或子过程将具有足够频率产生数据以便统计管理；
  8. 过程或子过程关联的度量方法与度量数据质量足够好。

技术过程大致可分为两类：开发性活动（需求开发、软件设计、编码实现、产品集成等，工作量占比大，对生产率或工期影响大）与验证性活动（技术评审、代码走查、测试等，重点关注缺陷移除，对交付质量影响更大）。

4.3.3 建立度量体系及数据收集

建立度量属性时，除各过程能力的“结果数据”外，须重点识别对过程能力结果产生潜在影响的“过程数据”。识别过程数据可采用思维导图方式，从人、机、料、法、环、测等方面识别影响因子。信息系统建设项目中人的因素影响比重较大，包括人员级别、数量、技能、业务熟练程度、角色完整程度等。

选择度量时需要考虑的准则主要包括：①与组织质量和过程性能目标适合；②全面覆盖产品全生命周期；③可操作；④清晰定义收集频率；⑤可控；⑥能代表使用者对有效过程的观点。

选择度量后应对其进行可操作的定义，包括意义说明、度量公式、度量数据、数据来源、收集频率、负责人等，形成过程度量说明文件。度量体系建立后，需经组织内部各相关角色共同评审，并定期评估其可用性和有效性。

量化管理使用的技术通常包括过程性能基线、过程性能模型、控制图、变异分析、回归分析、置信区间或预测区间、敏感度分析、蒙特卡洛模拟和假设检验等。

4.3.4 建立过程性能基线（PPB）

建立 PPB 的目的是通过历史数据刻画组织当前各过程的能力，确定过程能力的稳定范围，为管理决策提供数据化支持，并为后续项目的估算、计划与管理提供可参考的数据基准。

步骤：获取所需数据 → 分析数据特征 → 建立过程性能基线 → 发布和维护过程性能基线。

  1. 获取所需数据：建立过程能力基线必须确保足够的样本数量，通常初始样本数据应不少于 32 个；
  2. 分析数据特征：验证数据特征，判断是否需要分组；可用正态性检验判断是否符合正态分布，对不符合的数据可能需要分组；
  3. 建立基线：可用控制图建立，以历史能力均值作为中心线（CL），以中心线上 3 个标准差为控制上限（UCL），下 3 个标准差为控制下限（LCL）；
  4. 发布和维护：协调管理层、改进团队、各过程负责人评审，达成共识；当业务目标、过程性能目标或标准过程变化时及时维护。

过程能力异常判定准则（基于控制图）：

序号判定准则
1单独 1 个点掉出 3σ 控制范围之外
23 个连续的点里有至少 2 个点在中值的同一侧并且掉在 2σ 之外
35 个连续的点里至少有 4 个点在中值的同一侧并且掉在 1σ 之外
4至少有 8 个连续的点掉在中值的同一侧
5连续 7 个点在中心线同一侧，或连续 7 个点持续上升或下降

对异常数据需深入分析原因：属于特殊成因的，必须识别该成因内容，删除或校准数据后再使用；属于正常成因（过程存在的“噪声”）的，则需接纳该数据。

过程性能基线代表组织在一定条件之内的能力范围，建立时需注明前提条件范围。例如：项目工期偏差率控制在 10%～20% 的前提是项目经理级别均为 P6～P9 级；超出前提条件范围时该基线很可能发生变化。

4.3.5 建立过程性能模型（PPM）

PPM 的目的在于依据组织的可量化目标，使用已建立的度量体系及过程性能基线，通过回归的方式识别目标与过程因子之间的解释关系，实现对目标量化预测与解释，支撑目标分解与跟踪。

步骤：识别建模因子 → 建立过程性能模型 → 检验过程性能模型 → 评审和发布。

1. 识别建模因子

PPM 最显著的特征是包含可控因子。首先识别组织的质量与过程性能目标作为模型的输出（Outcome），然后识别与输出相关的过程能力因子，且必须包含可控因子。识别方法包括鱼骨图、德尔菲法或头脑风暴等。使用 Pearson 相关系数判定各因子与结果的相关性：

相关系数绝对值相关性
0.8 ≤ |r| ≤ 1强相关
0.5 ≤ |r| < 0.8中度相关
0.3 ≤ |r| < 0.5弱相关
0 ≤ |r| < 0.3基本不相关

通常选择相关性相对较大的因子参与建模；同时，各因子之间不可存在较高相关性，否则会引起多重共线问题。

2. 建立模型

由于影响最终交付质量与过程性能的因素较多，直接面向最终目标建模难度大、解释变量过多。组织可采用多层级模型：第一层级面向最终质量与过程性能目标建模，确保目标可预测和有效分解；第二层级面向需求开发、设计、编码、测试和评审等过程建模，实现目标向过程可控因子的分解。

3. 验证模型

  • 显著性：参与建模的每个因子的 P 值小于 0.05 时，认为该因子与模型结果显著相关，可以保留；
  • 判定系数：R-sq 越趋近于 1，模型可靠性越高；通常 R-sq 小于 0.7 认为模型可靠性较弱，需要重新选择因子；
  • 逻辑验证：逐个验证因子与结果输出之间的逻辑关系，避免多重共线导致的逻辑混乱；
  • 残差验证：对残差建立散点图判断正态性、直方图判断趋势、趋势图判断残留随时间的变化。

4. 评审和发布：协调管理层、改进团队及各过程负责人评审，取得各干系人共识。

4.4 项目级量化管理

4.4.1 项目过程性能目标定义

组织每个项目启动时，项目团队应依据组织级质量与过程性能目标要求、客户或服务对象交付要求及其他相关干系人的管理要求，结合项目团队自身过程能力数据，设定项目质量与过程性能目标。该目标需优先保证客户或服务对象要求，同时兼顾组织及其他干系人需要。

目标设定后，项目管理者可使用 PPB 和 PPM，采用蒙特卡洛模拟的方式预测目标达成的概率。对达成概率未达预期的情况，应识别风险、论证目标合理性并制定应对措施。

4.4.2 过程优化组合

项目建设的各个过程存在不同的子过程或执行方式，不同过程执行方式的性能数据存在分组，说明不同的过程组合方案可带来不同的质量与过程性能结果。

项目目标通常有多个，对过程执行方案组合的选择需要同时权衡多个目标的达成情况。由于各过程的基线分组较多，可使用蒙特卡洛模拟方法遍历每一种过程组合，从而判定满足目标的最优过程组合方案。

4.4.3 过程性能监控

目标分解是将项目目标量化分解至各过程或阶段，再分解至关键影响因子；过程性能监控是目标分解的逆向过程：首先监控关键影响因子是否满足分解要求，其次监控过程性能的稳定性和符合性，最后监控整个项目目标的达成情况。

对已选择的关键过程，项目团队可采用统计或其他量化技术主动监控过程能力：针对每个过程收集度量数据（如编码过程中每个任务的效率数据、每次代码走查发现的缺陷密度），使用控制图分析并监控性能。

过程性能的量化监控至少包含两方面：①监控过程性能是否稳定，可根据控制图稳定性判定准则通过小概率事件识别异常并解决；②监控过程性能是否满足规格要求，分解到该过程性能的目标即可作为规格上限（USL）和下限（LSL），通过对比 UCL/LCL 与 USL/LSL 判断。

当过程性能出现不稳定或不能满足规格要求时，需识别影响因素，开展根本原因分析，并预防同类问题再次发生。

4.4.4 项目性能预测

在各过程性能的稳定性及符合性满足后，需要在每个阶段或里程碑处，对项目最终目标的达成性进行量化预测。

在项目每个阶段或里程碑完成时，该阶段的性能数据将不再是基线中的分布值，而变为实际值。此时使用蒙特卡洛模拟，以已完成阶段的实际值和未完成阶段的基线值重新预测目标达成概率，可得到更新的达成概率。根据组织设置的置信区间判断是否在可控范围内；如信心不足，需调整后续里程碑或阶段的分解目标。

项目最终结束时，项目团队需根据实际数据计算目标达成情况，量化总结分析，并将经验教训、过程性能数据贡献给组织，作为 PPB、PPM 更新的依据。
