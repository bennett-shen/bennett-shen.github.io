为什么是 VuePress + Plume

静态站点工具很多，最后的取舍往往不在功能多少，而在「写完之后还要不要维护」。

三种常见选择

方案优势代价
纯 Markdown 托管零成本导航、搜索、标签全靠手工
通用 SSG灵活需要自己拼主题与插件
VuePress + Plume文档/博客一体，能力内置需要 Node 环境与构建步骤

决定性的两点

一是内容组织方式。 Plume 用集合（collection）管内容：一个目录就是一个内容单元，post 出博客，doc 出文档。新增一篇文章，列表、标签、归档自动更新，不需要改配置。

二是主题能力已经收好了。 搜索、代码组、提示容器、文件树、明暗主题、SEO 元信息都在主题里，不用为了一个功能去翻插件文档。

代价也说清楚

  • 需要 Node 环境，纯写作场景比在线编辑器重。
  • 构建时间随内容量增长，长文多图时需要留意构建缓存。

一个实际建议

如果站点规模不大，把 cache 保持默认的 filesystem 即可；只有当内容量达到几百篇、构建超过一分钟时，才需要考虑拆站。

对「既要写文档又要写博客」的个人站点来说，这套组合的性价比很高。
