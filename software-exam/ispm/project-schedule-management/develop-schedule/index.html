7 制订进度计划

约 3699 字大约 12 分钟

2026-11-22

制订进度计划是分析活动顺序、持续时间、资源需求和进度制约因素，创建进度模型，从而落实项目执行和监控的过程。主要作用是为完成项目活动而制定具有计划日期的进度模型，需要在整个项目期间开展。

制订可行的进度计划是一个反复进行的过程。编制时需审查和修正持续时间估算、资源估算和进度储备，并在经批准后作为基准用于跟踪项目进度。

关键步骤：

  1. 定义项目里程碑，识别活动并排列活动顺序，估算持续时间，确定活动的开始和完成日期；
  2. 由分配至各个活动的项目人员审查其被分配的活动；
  3. 项目人员确认开始和完成日期与资源日历及其他项目或任务没有冲突，从而确认计划日期的有效性；
  4. 分析进度计划，确定是否存在逻辑关系冲突，以及在批准并将其作为基准前是否需要资源平衡，并同步修订和维护进度模型。
输入工具与技术输出
项目管理计划（进度管理计划、范围基准）、项目文件（假设日志、风险登记册、活动属性、活动清单、里程碑清单、项目进度网络图、估算依据、持续时间估算、经验教训、资源需求、项目团队派工单、资源日历）、协议、事业环境因素、组织过程资产进度网络分析、关键路径法、资源优化、数据分析、提前量和滞后量、进度压缩、计划评审技术、项目管理信息系统、敏捷或适应型发布规划进度基准、项目进度计划、进度数据、项目日历、变更请求、项目管理计划（更新）、项目文件（更新）

7.1 进度网络分析

进度网络分析是创建项目进度模型的综合技术，关注两点：①当多个路径在同一时间点汇聚或分叉时，评估汇总进度储备的必要性，以减少进度落后的可能性；②审查网络，查看关键路径是否存在高风险活动或具有较多提前量的活动，是否需要使用进度储备或执行风险应对计划来降低关键路径的风险。该过程反复进行，直到创建出可行的进度模型。

7.2 关键路径法

关键路径是项目中时间最长的活动顺序，决定着可能的项目最短工期；最长路径的总浮动时间通常为零。关键路径法用于在进度模型中估算项目的最短工期，确定逻辑网络路径的进度灵活性，并计算关键路径、总浮动时间和自由浮动时间。

关键路径法有 2 条规则：

  1. 某项活动的最早开始时间必须相同或晚于直接指向这项活动的最早结束时间中的最晚时间；
  2. 某项活动的最迟结束时间必须相同或早于该活动直接指向的所有活动最迟开始时间中的最早时间。
正向计算（从第一个活动到最后一个活动，推算最早完工时间）
  ES = max{ 各紧前活动的 EF }   多个紧前活动时取最晚者，并计入搭接（提前量/滞后量）
  EF = ES + 工期
反向计算（从最后一个活动到第一个活动，推算最晚完工时间）
  LF = min{ 各紧后活动的 LS }   多个紧后活动时取最早者，并计入搭接
  LS = LF − 工期
浮动时间
  总浮动时间 TF = LF − EF = LS − ES
  自由浮动时间 FF = min{ 紧后活动的 ES } − 本活动 EF

在不考虑任何资源限制的情况下，按上述正向、反向推算即可得到所有活动的最早开始、最早结束、最晚开始和最晚完成日期。由此得到的日期不一定就是项目进度计划，而只是把既定参数（持续时间、逻辑关系、提前量、滞后量和其他已知制约因素）输入进度模型后的一种结果，表明活动可以在该时段内实施。

对比项总浮动时间自由浮动时间
定义在任一网络路径上，进度活动可以从最早开始日期推迟或拖延，而不至于延误项目完成日期或违反进度制约因素的时间在不延误任何紧后活动的最早开始日期或不违反进度制约因素的前提下，某活动可以推迟的时间量
计算LF − EF，或 LS − ES紧后活动 ES 的最小值 − 本活动 EF
关系关键路径上活动的总浮动时间通常为零自由浮动时间 ≤ 总浮动时间

进度网络图可能有多条关键路径。为使网络路径的总浮动时间为零或正值，可能需要调整活动持续时间（增加资源或缩减范围时）、逻辑关系（针对选择性依赖关系时）、提前量和滞后量或其他进度制约因素。

7.3 资源优化

资源优化是根据资源供需情况调整进度模型的技术，通过调整活动的开始和完成日期，使计划使用的资源等于或少于可用资源。包括资源平衡与资源平滑两种技术，区别是高频考点：

对比项资源平衡（Resource Leveling）资源平滑（Resource Smoothing）
目的在资源需求与资源供给之间取得平衡，按资源制约因素调整开始和完成日期；也可为保持资源使用量均衡而做调整活动，使项目资源需求不超过预定的资源限制
触发场景共享资源或关键资源只在特定时间可用且数量有限，如同一资源在同一时段被分配至两个或多个活动资源需求在某一时段超出负荷，但相关活动有可用的浮动时间
对关键路径往往导致关键路径改变，通常是延长关键路径、推迟完工日期不会改变关键路径，完工日期也不会延迟
手段与局限可用浮动时间平衡资源，但调整后项目工期可能变长活动只在自由浮动时间和总浮动时间内延迟，因此可能无法实现所有资源的优化

教材示例中，同一工程师同时承担 B、C 两项活动造成超负荷，属资源平衡场景，平衡后工期由 4 天变为 5 天；若超负荷活动 D 不在关键路径上且有 1 天总浮动时间，则用滞后量把 D 安排到第 3 天即可，属资源平滑，不影响整体工期。

7.4 数据分析

  • 假设情景分析：对各种情景进行评估，预测其对项目目标的积极或消极影响，即分析“如果情景 X 出现，情况会怎样”，据此评估进度计划在不同条件下的可行性，并为应对意外情况编制进度储备和应对计划。
  • 模拟：把单个项目风险和不确定性的其他来源模型化，以评估其对项目目标的潜在影响。最常见的模拟技术是蒙特卡罗分析，它利用风险和其他不确定资源计算整个项目可能的进度结果。

7.5 进度压缩

进度压缩是在不缩减项目范围的前提下，缩短或加快进度工期，以满足进度制约因素、强制日期或其他进度目标。包括 2 种技术：

对比项赶工（Crashing）快速跟进（Fast Tracking）
做法增加资源，以最小的成本代价压缩工期，如批准加班、增加额外资源、支付加急费用将正常情况下按顺序进行的活动或阶段改为至少部分并行开展
适用条件只适用于通过增加资源就能缩短持续时间且位于关键路径上的活动只适用于能够通过并行活动缩短关键路径上项目工期的情况
主要代价并非总是切实可行，可能导致风险和成本增加可能造成返工和风险增加；使用提前量会增加协调工作并增加质量风险，也可能增加成本

7.6 计划评审技术（PERT）

计划评审技术（Program Evaluation and Review Technique，PERT）又称三点估算技术，其理论基础是假设项目持续时间以及整个项目完成时间是随机的，且服从某种概率分布，因此可以估计整个项目在某个时间内完成的概率。

单活动期望持续时间（假定服从 Beta 分布）
  Te = (To + 4Tm + Tp) / 6
单活动持续时间方差与标准差
  σ² = ((Tp − To) / 6)²      σ = (Tp − To) / 6
项目级汇总（各活动顺次进行、时间相互独立）
  T = ΣTe        σ项目² = Σσ²        σ项目 = √(Σσ²)

教材 OA 系统示例（需求分析、设计编码、测试、安装部署 4 个活动顺次进行）：

活动乐观 To最可能 Tm悲观 Tp期望 Te方差 σ²
需求分析71115111.778
设计编码1320352113.445
测试57970.445
安装部署51315122.778
合计———5118.446

项目标准差 σ = √18.446 ≈ 4.3 天。据此按正态分布规律：

  • ±1σ（46.7 ~ 55.3 天）内完成的概率约 68%；
  • ±2σ（42.4 ~ 59.6 天）内完成的概率约 95%；
  • ±3σ（38.1 ~ 63.9 天）内完成的概率约 99%；
  • 要求 39 天内完成的概率约 0.5%，几乎为零，说明项目有不可压缩的最小周期；
  • 查标准正态分布表，60 天内完成的概率约 0.9817，53 天内完成的概率约 0.6808。

PERT 与 CPM 在项目进度规划中应用非常广泛：CPM 用单一确定工期求最长路径，PERT 用三点估算处理不确定性并给出完工概率。

7.7 输出

1. 进度基准：是经过批准的进度模型，只有通过正式的变更控制程序才能变更，用作与实际结果进行比较的依据。经干系人接受和批准后，进度基准包含基准开始日期和基准结束日期；监控过程中用实际开始和完成日期与批准的基准日期比较，以确定是否存在偏差。进度基准是项目管理计划的组成部分。

2. 项目进度计划：是进度模型的输出，为各个相互关联的活动标注计划日期、持续时间、里程碑和所需资源等，至少要包括每个活动的计划开始日期与计划完成日期。在未确认资源分配和计划开始与完成日期之前，进度计划都只是初步的。

表现形式说明
横道图（甘特图）纵向列示活动、横向列示日期，用横条表示活动自开始至完成日期的持续时间；相对易读、比较常用，属概括性进度计划
里程碑图与横道图类似，但仅标示主要可交付成果和关键外部接口的计划开始或完成日期，属里程碑进度计划
项目进度网络图通常用活动节点法绘制，没有时间刻度，纯粹显示活动及其相互关系；带时间刻度的称为时标图，属详细进度计划

3. 进度数据：用以描述和控制进度计划的信息集合，至少包括进度里程碑、进度活动、活动属性，以及已知的全部假设条件与制约因素。支持细节常包括：按时段列的资源需求（常以资源直方图表示）、备选的进度计划（最好/最坏情况、经/未经资源平衡、有/无强制日期）、使用的进度储备；还可包括资源直方图、现金流预测、订购与交付进度安排等。

4. 项目日历：规定可以开展进度活动的可用工作日和工作班次，把可用于开展进度活动的时间段与不可用时间段区分开来。一个进度模型中可能需要采用不止一个项目日历，因为有些活动需要不同的工作时段。

5. 变更请求与计划更新：修改项目范围或进度计划后，可能对范围基准和/或项目管理计划其他组成部分提出变更请求；可能更新的组件包括进度管理计划和成本基准；可能更新的项目文件包括活动属性、假设日志、持续时间估算、经验教训登记册、资源需求、风险登记册。
